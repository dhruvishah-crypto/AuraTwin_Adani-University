# RespiraTwin: Multimodal Healthcare Digital Twin for Asthma Exacerbation Risk Forecasting & What-If Simulation

> **MANDATORY CLINICAL DISCLAIMER**: RespiraTwin is a simulation-based research prototype and algorithmic proof-of-concept. All event labels, clinical outcomes, ambient pollution values, and wearable physiological signals are generated by an epidemiological and physiological simulator. RespiraTwin does **not** claim clinical accuracy. Results measure the learning of a simulated process, not real-world clinical prognosis. It must **never** be used for clinical diagnosis, treatment planning, or medication alteration.

---

# Problem Statement & Healthcare Use Case

Asthma affects over 300 million individuals globally, causing acute exacerbations (attacks) that drive frequent emergency department visits, hospitalizations, and substantial morbidity. While acute exacerbations are triggered by a convergence of ambient air pollution (PM2.5/PM10 spikes), poor controller medication adherence, viral prodromes, and individual physiological vulnerability, current clinical management remains predominantly reactive—patients seek care only after severe bronchoconstriction and respiratory distress manifest.

### The Healthcare Use Case
**RespiraTwin** introduces a point-of-care predictive digital twin for proactive asthma management:
1. **Multimodal Data Fusion**: Fuses static Electronic Health Record (EHR) profiles (demographics, baseline vitals, clinical asthma severity, comorbidities, prescribed inhalers) with continuous ambient environmental exposure (hourly synthetic pollution series (illustrative urban Delhi-range levels; not real measurements)) and simulated wearable streams (acoustic respiratory rate, PPG pulse oximetry, heart rate, autonomic heart rate variability [HRV RMSSD], nocturnal sleep duration, and digital patient symptom/rescue inhaler logs).
2. **Proactive 24-Hour Early-Warning**: Predicts the calibrated probability and 0-100 Risk Score of an exacerbation attack occurring in the subsequent 24 hours ($t \to t+24\text{h}$), providing clinicians and patients with actionable lead time (median 12.0 hours) before acute symptoms peak.
3. **Transparent Clinical Explainability**: Translates complex machine learning inferences into signal-family attributions (*Pollution*, *Breathing & Oxygenation*, *Rescue & Symptoms*, *Adherence*, *Baseline History*) and human-readable clinical reason code bullets derived from deviations against the patient's personalized baseline.
4. **Counterfactual What-If Simulation**: Enables clinicians to test hypothetical interventions ("model response to hypothetical input")—such as air purifiers, clean-air shelter, or rescue medication—by coherently updating all dependent rolling features without mutating historical observation records.

# Technical Stack & ML Details

### Technical Stack
- **Programming Language**: Python 3.10+
- **Machine Learning**: `scikit-learn` (`HistGradientBoostingClassifier`, `RandomForestClassifier`, `LogisticRegression`, `IsotonicRegression`, `SimpleImputer`, `StandardScaler`, `Pipeline`)
- **Data Engineering**: `pandas`, `numpy`, `joblib`

- **Interactive Visualizations**: `Plotly` (`plotly.graph_objects`, `plotly.subplots` for stacked synchronous telemetry charts)
- **Verification & Testing**: `pytest` (45 automated unit tests covering leakage, feature parity, monotonic constraints, baseline windows, and data quality)

### Machine Learning Architecture & Operational Selection
- **Feature Engineering Pipeline (`src/build_features.py`)**: 52 strictly past-looking features capturing multiscale rolling environmental exposures (6h, 24h, 72h means and maximums), physiological deviations from personalized baseline norms, autonomic HRV trends, oxygen saturation deficits, circadian-aligned sleep deficits, and rescue inhaler velocity.
- **Personalized Baseline Computation**: Dynamically computed over a 14-to-30-day lookback window that **explicitly excludes the most recent 72 hours**. This design ensures acute pre-attack prodromal deterioration does not inflate or contaminate the patient's stable physiological baseline norm.
- **Monotonic HistGradientBoosting (Operational Model)**: Incorporates 25 pathophysiological domain constraints. Enforces positive monotonicity on environmental PM2.5, respiratory rate deviations, and rescue puffs, alongside negative monotonicity on arterial oxygen saturation (SpO2) and controller adherence.
- **Post-Hoc Isotonic Probability Calibration**: Fitted strictly on validation split patient hours to ensure that predicted risk probabilities accurately reflect empirical event rates (Brier score $0.0526$, calibration slope $0.9786$, intercept $-0.0041$).
- **Comparative Trade-off & Operational Wording**: On the holdout test set across true **at-risk hours** (excluding active attacks and recovery/refractory periods), the operational constrained HistGradientBoosting model **matches Random Forest within about 0.003 PR-AUC** (Constrained HGB: `0.4951` validation / `0.4977` test vs. Random Forest: `0.4978` validation / `0.5048` test; val gap = $0.0027$). On **all hours**, the operational model trails Random Forest (Test PR-AUC: `0.4688` vs. `0.4782`) because unconstrained decision trees exploit non-monotonic splits on recovery-period vitals where hazard is artificially zero, whereas constrained HGB remains bound by pathophysiological domain priors to achieve 100% monotonicity across all what-if scenario sweeps.

### 3. False Alert Episode Accounting & Stricter Breakdown
- **Definition of False Alert Episode**: Consecutive hourly alerts for a patient within a **6-hour cooldown window** are clustered into a single distinct **alert episode** anchored at the earliest alert timestamp $T_{\text{alert}}$. An alert episode is classified as a **false alert episode** if **no true exacerbation onset occurs for that patient in the subsequent 24 hours** $(T_{\text{alert}}, T_{\text{alert}} + 24\text{h}]$.
- **Stricter Breakdown from `models/metrics.json`**:
  - Total Alert Episodes: **656**
  - Followed by true onset within 24h (True Positive Alert Episodes): **321**
  - Alert episodes occurring during an active episode $[T_{\text{onset}}, T_{\text{end}})$: **32**
  - Alert episodes occurring during post-episode recovery $[T_{\text{end}}, T_{\text{end}} + 18\text{h})$: **0**
  - Alert episodes occurring during active or recovery periods: **32**

> **Empirical Adherence Diagnosis & Tree Split Analysis**:
> In-depth diagnostic profiling of the trained operational model and cohort reveals why isolated 7-day adherence produces small risk deltas:
> 1. **Ceiling Distribution**: In the synthetic cohort, adherence exhibits strong ceiling clustering—**73.5% of train hours and 77.3% of test hours are at 100% adherence** (mean $0.877 \pm 0.207$ train, $0.904 \pm 0.184$ test; median $1.000$; only $21.3\%$ train / $17.4\%$ test hours fall below the $80\%$ sub-optimal threshold).
> 2. **Ensemble Tree Splits**: Across all 600 decision trees (32,330 internal decision splits) in the operational constrained HistGradientBoosting ensemble, only **284 splits (0.878%)** utilize `controller_adherence_7d`.
> 3. **Validation Permutation Importance**: On the validation set, permuting `controller_adherence_7d` drops PR-AUC by $+0.006205 \pm 0.000349$ (ranked #15 out of 52 features). Tree splits are instead heavily concentrated on acute respiratory deterioration signals (`spo2_min_24h` importance: $+0.2364$, `spo2_drop_from_baseline`: $+0.1576$, `rr_recent_vs_usual`: $+0.0977$).
> 4. **Combined Clinical Preset**: In real-world asthma care, non-adherence rarely triggers acute bronchospasm directly in a vacuum; rather, omitted anti-inflammatory medication escalates airway irritability, producing symptoms and triggering compensatory rescue inhaler use. Accordingly, the dashboard's "Adherence Lapse" preset implements a **combined scenario (adherence drop + rescue escalation)** to accurately mirror this clinical pathway.

# Datasets & Provenance

All datasets reside in the `data/` directory and are completely synthetic:
1. **Synthetic EHR Cohort (`data/patients.csv`, `data/sample_patients.csv`)**: 300 synthetic patient records containing demographic and clinical attributes (age, sex, clinical asthma severity, 12-month exacerbation history, baseline respiratory rate, baseline pulse oximetry, prescribed controller inhalers, and comorbidities). Generated using controlled multivariate Gaussian and categorical distributions reflecting published clinical asthma literature.
2. **Hidden Latent Truth (`data/latent_truth.csv`)**: Patient-specific latent vulnerability factors representing unobserved biological susceptibility (e.g., airway hyper-reactivity, genetic predisposition). Stored in strict physical isolation; never accessed by the feature engineering pipeline or machine learning models.
3. **synthetic pollution series (`data/sample_pollution.csv`)**: 60 days of hourly continuous PM2.5 and PM10 concentrations synthesized with seasonal background trends, diurnal vehicular rush-hour peaks, and episodic meteorological inversions (illustrative urban Delhi-range levels; not real measurements). To substitute with real physical monitoring station data, download hourly CPCB CCR or OpenAQ data using the instructions in `data/sample_pollution.json`.
4. **Simulated Wearable Stream (`data/patient_timeseries.csv`, `data/sample_wearables.csv`)**: 432,000 hourly observations capturing continuous acoustic respiratory rate, PPG pulse oximetry, heart rate, autonomic HRV RMSSD, nocturnal sleep duration, digital rescue inhaler use logs, and patient symptom diary scores.

# Limitations & Ethics (DPDP / HIPAA, Synthetic Data Only)

1. **Zero Real Patient Data / Synthetic Only**: RespiraTwin was developed and evaluated **exclusively on synthetic data**. No real patient data, protected health information (PHI), or electronic medical records were collected, processed, or stored.
2. **Compliance with DPDP Act 2023 & HIPAA**: Because all records are synthetic mathematical artifacts generated via pseudo-random simulation, no individual privacy rights under India's Digital Personal Data Protection (DPDP) Act 2023 or the US Health Insurance Portability and Accountability Act (HIPAA) are implicated.
3. **Simulation-to-Reality Gap**: Machine learning models trained on simulated epidemiological processes will reflect the inductive biases, mathematical assumptions, and simplified dynamics of the underlying generator. Monotonic relationships enforced here represent pathophysiological clinical priors, but real-world clinical deployment would require rigorous prospective observational trials and regulatory clearance.
4. **Algorithmic Guardrails**: The dashboard implements persistent banners ("SYNTHETIC PATIENT RECORD", "SIMULATED SCENARIO"), mandatory clinical disclaimers on every view, and a fixed footer: *"Simulation-based demo; not for clinical use."*

# How to Run

### 1. Environment Setup & Dependencies
```bash
# Clone the repository
git clone <repo_url>
cd respiratwin

# Create and activate virtual environment
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

# Install required dependencies
pip install -r requirements.txt
```

### 2. Run Automated Test Suite (45 Unit Tests)
```bash
pytest -v
```

### 3. Launch Doctor-Facing Digital Twin Dashboard
```bash
streamlit run app.py
```
Open your browser at `http://localhost:8501`.

### 4. Optional: Recompute What-If Effect Sizes
```bash
python scratch/compute_whatif_effects.py
```

### 5. Optional: Full Synthetic Data Pipeline Regeneration
```bash
# Regenerate full cohort (300 patients, 60 days hourly)
python src/generate_data.py --num_patients 300 --seed 42 --output_dir data
python src/ingest_pollution.py --days 60 --city Delhi --seed 42 --output data/sample_pollution.csv
python src/simulate_wearables.py --days 60 --seed 42 --output data/patient_timeseries.csv
python src/build_features.py --output data/features.csv
python src/simulate_events.py --features data/features.csv --output data/labeled_dataset.csv
```
